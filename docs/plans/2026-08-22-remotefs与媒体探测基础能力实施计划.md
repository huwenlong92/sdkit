## 目标与实施顺序

本轮按以下顺序执行，不能倒置：

1. 在 sdkit 冻结 provider-neutral 的 `remotefs` 契约和错误语义。
2. 先实现 `local` driver，以本地挂载目录代表 NFS/SMB/WebDAV 等已经挂载到宿主机的 NAS，并验证契约不依赖网盘语义。
3. 实现 `baidupan` driver，复用 `pkg/execx`，完成账号会话隔离、分享转存、目录读取和带进度下载。
4. 独立实现媒体 `Prober` 契约和 `ffprobe` driver。
5. 完成公共包文档、契约测试和可选真实集成测试。
6. 公共包验收通过后由 sdingest 通过本地目录依赖接入，稳定后再由用户发布 tag。

## 已冻结的架构决策

- 模块名称使用 `remotefs`，不使用 `drive`、`filesource`、`pan` 或 `baidu` 作为公共抽象名称。
- sdkit 首版只提供可独立导入的 `pkg/remotefs` 协议契约和 driver，不新增 runtime capability、全局默认实例或 facade。
- 具体实现遵循 sdkit 现有目录习惯，放在 `pkg/remotefs/driver/<name>`；首批名称为 `local` 和 `baidupan`。
- `remotefs` 表达“从外部层级文件系统读取内容”；现有 `storage` 表达“向 local/S3/OSS/COS 保存和管理对象”。两者不互相依赖，由 sdingest 网关编排传输。
- `ffprobe` 不属于 `remotefs`。媒体探测只使用独立的 `pkg/media` 契约和 `pkg/media/ffprobe` 实现。
- Baidu 是首个云盘 driver，不是公共接口的设计中心。公共类型不得暴露 `baidupcs.FileDirectory`、BaiduPCS-Go 命令输出或百度错误码。
- `baidupan` driver 负责单实例内的账号会话隔离、CLI 进程控制和标准错误；调用方负责持有并关闭实例。
- connection/account 到 driver 实例的映射、复用、账号轮换、租约、冷却、权重、分布式并发和任务粘性属于 sdingest。sdkit 不提供隐式轮询或默认账号选择。

## 来源能力矩阵

首版契约按不同来源的真实差异设计，不能要求所有 driver 伪装成百度网盘：

| 来源类型 | Stat/List | 分页 | 下载到本地 | 流式 Open | 分享链接 | 账号内转存 | 删除/清理 | 典型实现 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 百度、夸克、阿里云盘、123 云盘 | 必需 | 通常需要 | 必需 | 可选 | 可选能力 | 可选能力 | 可选能力 | provider API 或隔离 CLI |
| FTP/SFTP | 必需 | driver 内适配 | 必需 | 通常支持 | 不适用 | 不适用 | 可选能力 | 协议客户端 |
| WebDAV/SMB | 必需 | driver 内适配 | 必需 | 通常支持 | 不适用 | 不适用 | 可选能力 | 协议客户端 |
| 已挂载 NAS/NFS/SMB | 必需 | 本地遍历 | 必需 | 支持 | 不适用 | 不适用 | 默认禁用 | `local` root |
| HTTP 直链 | Stat 能力有限 | 不适用 | 必需 | 支持 | 链接本身即引用 | 不适用 | 不适用 | 后续 `http` driver |

公共基础接口只包含所有层级文件来源都能稳定提供的能力。分享解析、账号内转存、流式读取、删除和健康检查使用小型可选接口，通过类型断言和统一 helper 发现，避免一个大接口迫使 FTP、NAS 实现无意义的方法。

## RemoteFS 公共契约草案

### 基础模型

- `Reference`：driver-neutral 的远端引用，至少包含 driver、connection、opaque ID 和规范化 path；业务层不得解析 opaque ID。
- `Entry`：名称、规范化路径、文件/目录类型、大小、修改时间、可选 checksum 和 provider metadata；不携带 provider SDK 原始对象。
- `ListOptions` / `ListPage`：显式分页游标、页大小和排序提示；禁止公共层提供一次性无上限 `ListAll`。
- `DownloadRequest` / `DownloadResult`：远端引用、本地目标、覆盖策略、最终路径、字节数和校验信息。
- `Progress`：使用 `TransferredBytes`、`TotalBytes`、`BytesPerSecond` 和阶段枚举，不继续向上暴露旧实现中的 `"12.3MB"` 字符串。

基础接口草案：

```go
type FileSystem interface {
	Driver() string
	Stat(ctx context.Context, ref Reference) (Entry, error)
	List(ctx context.Context, dir Reference, opts ListOptions) (ListPage, error)
	Download(ctx context.Context, req DownloadRequest, sink ProgressSink) (DownloadResult, error)
	Close() error
}
```

可选能力按小接口拆分：

```go
type ShareResolver interface {
	ResolveShare(ctx context.Context, req ShareRequest) (ShareResult, error)
}

type ShareStager interface {
	StageShare(ctx context.Context, req StageRequest) (StageResult, error)
}

type Opener interface {
	Open(ctx context.Context, ref Reference, opts OpenOptions) (io.ReadCloser, error)
}

type Remover interface {
	Remove(ctx context.Context, refs ...Reference) error
}

type HealthChecker interface {
	Check(ctx context.Context) (Health, error)
}
```

`FeaturesOf(fs)` 从实际接口实现推导能力，不维护可能与实现漂移的手写布尔配置。通用 `Walk` 基于分页 `List` 实现，必须支持 context 取消、最大深度、访问条数上限和调用方过滤函数。

### 错误语义

定义支持 `errors.Is` / `errors.As` 的统一错误：

- `ErrNotFound`
- `ErrUnauthenticated`
- `ErrPermissionDenied`
- `ErrRateLimited`
- `ErrQuotaExceeded`
- `ErrShareInvalid`
- `ErrShareExpired`
- `ErrSharePasswordInvalid`
- `ErrConflict`
- `ErrUnsupported`
- `ErrBinaryUnavailable`
- `ErrVersionUnsupported`
- `ErrTemporary`

provider 错误包装至少保留 `Operation`、`Driver`、可选 retry-after 和可脱敏诊断摘要。错误、日志和 progress event 不得包含 BDUSS、STOKEN、分享口令、完整 Cookie、对象存储密钥或未经脱敏的命令参数。

## 多账号与会话隔离

### sdkit driver 负责

- `pkg/remotefs.Registry` 只负责按显式 driver、connection 和配置创建 `FileSystem`，不缓存实例、不管理默认 connection，也不承担账号选择。
- 同一 provider 的多个账号必须拥有独立配置目录和独立 client/session，禁止复用进程级全局登录态。
- `baidupan` 必须为每个账号设置独立 `BAIDUPCS_GO_CONFIG_DIR`，目录权限为 `0700`，配置文件权限为 `0600`；账号标识进入路径前必须规范化或哈希，防止目录穿越。
- 不调用全局裸 `BaiduPCS-Go who/login/logout/cd`；每一次 CLI 调用都必须显式注入账号配置目录。
- 不同百度账号可以并发；同一账号中会修改 CLI 当前目录或 session 配置的操作必须由 driver 串行化。首版只保证单进程内串行，跨进程同账号互斥由 sdingest 分布式租约保证并写入文档约束。
- `Close` 只能释放当前实例资源，不能登出或删除其他账号配置。

同名 connection 实例复用、实例生命周期、账号密文持久化、账号池选择、限流冷却、分布式租约和任务粘性明确不属于 sdkit；它们由消费方根据业务模型实现。本计划只通过 `Reference.Connection`、registry factory 参数和文档保留必要边界。

## BaiduPan driver 重写策略

旧代码中以下行为可以作为需求和解析样本保留：账号登录校验、目录读取、分享转存、递归获取文件、下载进度、临时目录和转存后清理。

以下实现不得直接迁移：

- `PcsPool`、可重置 mutex、全局登录态和 `login/logout/who/cd` 组合。
- 直接使用 `os/exec`、手工 goroutine 写 stdin、手写 `scanCRLF` 和不受 context 控制的下载。
- `fmt.Println`、直接记录完整命令输出和凭据相关配置。
- 返回 `baidupcs.FileDirectory` 等第三方类型。
- `ListVideos`、剧集数字排序、随机 `/download/<xid>`、数据库状态更新、Asynq task 和 OSS/COS 上传；这些是旧业务语义，不属于 driver。
- 无分页、无循环检测、无上限的递归遍历。

新 driver 要求：

1. 所有 CLI 调用通过可注入的 `Runner` 执行，生产实现复用 `pkg/execx`；单元测试使用 fake runner，不依赖真实账号或二进制。
2. 复用 `execx.RunOutput`、`RunStream`、`WithEnv`、`WithSplitMode(SplitCRLF)`、`WithMergeStderr`、`WithInputString` 和进程组清理，不在 driver 复制进程管理代码。
3. 实现开始前做一次受控 transport spike：`Stat/List` 优先使用结构化 API；分享转存和下载使用 BaiduPCS-Go CLI。无论最终选择 CLI 还是隔离的 provider client，第三方结构和错误都必须止于 `driver/baidupan`。
4. 解析器使用脱敏后的 golden fixtures 覆盖成功、文件重复、路径不存在、认证失效、分享口令错误、分享失效、限流、配额不足、下载进度和保存路径；未知输出返回带摘要的 typed error，不能误判成功。
5. `BinaryPath`、允许的 BaiduPCS-Go 版本范围、config root、下载并发和下载模式显式配置；启动/健康检查校验二进制存在和版本兼容，不自动联网安装或更新二进制。
6. 下载目标由调用方提供，driver 返回最终文件路径；必须防止远端文件名造成目标目录穿越。中断后是否保留 partial file 由显式策略决定。
7. 分享转存目标使用绝对路径；因 CLI 转存依赖当前网盘目录，同账号内的“切目录 + 转存”必须位于同一个临界区，不能让两个任务串台。
8. driver 不执行 OSS/COS 上传，也不决定下载完成后何时删除远端转存目录。

## Local driver 作为第二类实现

`local` 不是测试 mock，而是首版正式 driver，可直接覆盖“NAS 已通过 NFS/SMB 挂载到宿主机”的场景，同时验证公共契约没有百度特有假设。

- 配置一个不可变 root，所有 path 经过清理和 root confinement 校验。
- 拒绝 `..`、绝对路径注入以及通过符号链接逃逸 root。
- 支持 `Stat`、分页 `List`、`Download` 和可选 `Open`。
- `Remove` 默认不启用；即使实现也必须由显式配置开启，避免调用方对来源文件产生意外破坏。
- 契约测试先跑 `local`，再让 `baidupan` 复用相同的 driver contract suite。

后续 FTP、SFTP、WebDAV、SMB、夸克、阿里云盘和 123 云盘只新增 driver 与 provider-specific 配置，不修改 `Entry`、分页、下载进度和标准错误的核心语义；若新增能力确实不是现有可选接口能表达，再以向后兼容方式扩展小接口。

## 媒体探测与 ffprobe

媒体探测是独立能力，不依赖 RemoteFS 或 storage：

```go
type Prober interface {
	Probe(ctx context.Context, input Input, opts ProbeOptions) (Info, error)
}
```

首版 `Info` 至少规范化：

- 容器格式、时长、总码率和文件大小。
- 视频流 codec、profile、width、height、像素格式、帧率、旋转信息和 HDR/色彩字段。
- 音频流 codec、采样率、声道数和语言。
- 字幕流 codec 和语言。
- 原始 stream index，便于业务层定位具体轨道。

`pkg/media/ffprobe` 使用固定参数输出 JSON，通过 `pkg/execx.RunOutput` 执行；调用方负责 context timeout，driver 负责输出上限、JSON 校验、有理数帧率解析和 typed error。首版只承诺本地文件输入，远程 URL 探测待安全策略、网络访问和 header/credential 传递模型明确后再扩展。

调用方直接构造并持有 `Prober`；sdkit 首版不提供具名 Manager 或全局默认 Prober。不得把短剧集数识别、文件命名规则、清晰度业务标签或 Asset 建档写入 `pkg/media`。

## 测试与验收门禁

至少执行：

```bash
go test ./tests/pkg/remotefs/...
go test ./tests/pkg/media/...
go test -race ./tests/pkg/remotefs/...
go test ./...
git diff --check
```

如果 `baidupan` 使用 build tag，还需执行带 tag 的对应测试。真实百度账号和真实 ffprobe 文件只属于 opt-in integration suite，不能成为默认单元测试的前置条件。

验收必须同时满足：

- `local` 与 `baidupan` 通过同一套基础 driver contract tests。
- 两个百度账号并发执行时，各自命令只看到自己的 `BAIDUPCS_GO_CONFIG_DIR`，不存在登录态或工作目录串号。
- 同一账号的转存临界区不会和另一任务交叉；context 取消后 CLI 及子进程能够退出。
- 未安装二进制、版本不支持、认证失效、限流、配额不足、分享失效、路径不存在和下载中断均有可判断错误。
- 日志、错误、测试 fixture 和文档不出现真实凭据。
- ffprobe 输出完全映射为 `pkg/media` 模型，不向调用方暴露命令 JSON 结构作为稳定 API。
- `remotefs` 不依赖 DreamIP、GORM、Asynq、Gin 或 `storage`；`media` 不依赖 `remotefs`。

## 公共包交付门槛

满足以下条件后，消费方才开始业务接入：

1. sdkit public API 经至少 `local` 和 `baidupan` 两个 driver 验证并稳定。

3. `ffprobe` 能对下载后的本地视频输出规范化媒体信息。
4. 公共包文档足以让新项目不阅读 driver 内部代码即可接入。
5. 用户确认 public API、本地目录依赖方式和准备发布的 tag 范围。

## 明确不在本计划范围

- 夸克、阿里云盘、123 云盘、FTP、SFTP、WebDAV、SMB 的具体 driver 实现。
- sdingest 数据表、账号池、Worker、API、管理页面和 OSS/COS 业务编排。
- 自动下载或更新 BaiduPCS-Go、ffmpeg/ffprobe 二进制。
- 短剧剧集排序、剧名识别、manifest 业务规则、AI 识别和 Asset 建档。
- 生产凭据迁移及旧 `aideo-drive` 数据迁移。
